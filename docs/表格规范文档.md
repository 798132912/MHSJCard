# 魔法少女卡牌游戏表格规范文档

日期：2026-05-20

本文档记录策划 Excel 表和程序 CSV 的基础规范。

## 基本原则

- Excel 源表给策划编辑。
- CSV 导出表给程序读取。
- Excel 是唯一源数据，CSV 是导出产物。
- 当 Excel 和 CSV 不一致时，默认 CSV 过期或导出流程需要重跑；不能用旧 CSV 判断 Excel 配置错误。
- 除非明确执行“从 CSV 恢复 Excel”，否则不要把 CSV 旧值反向写回 Excel。
- Excel 和 CSV 文件名统一使用英文。
- 表格内第 1 行到第 3 行是固定表头区。
- 第 4 行开始才是正式数据。
- 导出 CSV 时，只导出第 1 行英文字段名和第 4 行以后的数据。
- 第 2 行字段类型和第 3 行中文注释不导出到 CSV。

## 三行表头规范

### 第 1 行：英文字段名

用于程序读取。

示例：

```text
id
effect_type
value
target
target_source
```

### 第 2 行：字段类型

用于限制输入，也方便程序解析。

常用类型：

```text
int
float
string
bool
int()
string()
enum
```

类型说明：

```text
int：整数
float：小数
string：字符串
bool：布尔值，建议写 true / false
int()：整数数组，多个值用分号分隔
string()：字符串数组，多个值用分号分隔
enum：枚举值，本质上通常用 int 表示
```

### 第 3 行：中文注释

用于策划查看字段含义。

示例：

```text
效果ID
效果类型枚举
数值，含义由效果类型决定
目标类型枚举
目标来源枚举
```

### 第 4 行开始：正式数据

第 4 行开始才是游戏数据。

## ID 规范

ID 尽量使用有规律的数字。

示例：

```text
100000-199999：玩家基础卡牌效果
200000-299999：敌人行动效果
300000-399999：状态效果
400000-499999：道具效果
```

具体例子：

```text
100101：星光射击的普通伤害效果
100201：魔力防御的护盾效果
200001：堕落的学生袭击伤害效果
```

## 枚举规范

策划表中不要填写中文效果类型给程序读取。

错误示例：

```text
效果类型 = 获得资源
```

正确示例：

```text
effect_type = 100
```

中文含义写在注释文档或枚举说明中。

## CardEffect 表规则

`CardEffect` 的详细设计请查看：`CardEffect机制文档.md`

### effect_type

```text
100：修改资源
200：造成伤害
300：附加效果
400：抽牌
500：弃牌
```

`value` 是复合参数字段，由 `effect_type` 决定解析方式。

示例：

```text
effect_type = 100 修改资源
value = 50,5
含义：获得 5 点魔力护盾
```

```text
effect_type = 200 造成伤害
value = 10,5
含义：造成 5 点普通伤害
```

```text
effect_type = 300 附加效果
value = 300001,1
含义：附加 1 层 300001 号效果，也就是冰甲
```

一维参数使用英文逗号：

```text
10,5
```

二维参数使用英文分号：

```text
10,5;40,2
```

### target

```text
1：自身
2：敌方单体
3：敌方群体
```

`target` 按出牌者阵营解释，不使用固定“玩家”目标。
例如玩家卡 `1` 是玩家自身，怪物行动 `1` 是怪物自身；玩家卡 `2` 指怪物，怪物行动 `2` 指玩家。

### target_source

```text
10：玩家选择目标
20：继承卡牌目标
30：卡牌固定目标
40：效果自身选择目标
50：来源自身
60：随机合法目标
70：全部合法目标
0：无目标
```

### trigger_timing

时机属于代码层枚举，不单独做策划配置表。

```text
10：附加时
20：玩家回合开始时
30：玩家回合结束时
40：敌人回合开始时
50：敌人回合结束时
60：受到伤害前
70：受到伤害后
80：造成伤害前
90：造成伤害后
100：出牌前
110：出牌后
120：解除变身时
130：战斗结束时
```

### duration_type

持续时间属于代码层枚举，不单独做策划配置表。

```text
10：瞬间
20：本回合
30：N 回合
40：本场战斗
50：当前变身期间
60：直到条件满足
70：永久
```

### damage_type

```text
0：无
10：普通伤害
40：穿透伤害
50：真实伤害
60：护盾破坏
```

### resource_type

```text
0：无
10：生命值
20：当前魔力
30：魔力上限
40：魔力防御
50：魔力护盾
60：发情值
70：敏感值
80：堕落值
```

`damage_type` 和 `resource_type` 不再作为 `CardEffect` 的独立字段存在。它们作为 `value` 的第一个参数出现，具体含义由 `effect_type` 决定。

## 导出规则

导出工具：

```text
导出策划表到CSV.bat
```

导出行为：

```text
读取 design_tables/excel/*.xlsx
跳过第 2 行字段类型
跳过第 3 行中文注释
输出 data/tables/*.csv
```

判断规则：

```text
Excel -> CSV 是唯一正常方向。
CSV diff 只能用于检查导出结果，不用于反向覆盖 Excel。
如果 CSV 与 Excel 不一致，先重新导出；仍有问题时检查导出脚本或 Excel 源表本身。
```

CSV 结果形态：

```text
第 1 行：英文字段名
第 2 行开始：正式数据
```
