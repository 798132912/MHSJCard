# Godot 卡牌游戏讨论记录

日期：2026-05-19  
主题：用 Godot 制作类似《杀戮尖塔》的卡牌游戏

## 项目目标

希望使用 Godot 制作一款类似《杀戮尖塔》的 roguelike deckbuilder 卡牌游戏。

具体世界观、资源命名和战斗资源设定拆分到独立文档：`游戏设定文档.md`。

最低战斗 UI 需求和建议节点命名拆分到独立文档：`最低战斗UI清单.md`。

数据表结构和策划表管线拆分到独立文档：`数据表结构说明.md`。

用户希望自己设计场景 UI，Codex 主要负责：

- 把 UI 场景拼进游戏
- 写交互逻辑
- 绑定节点和信号
- 做卡牌拖拽、悬停、目标选择、出牌反馈
- 搭建基础战斗流程
- 帮助选择合适的框架和学习资料

## 早期范围建议

建议先做一个最小可玩版本，不要一开始做完整游戏。

第一版目标：

1. 一个角色
2. 一个敌人
3. 10 张左右卡牌
4. 抽牌、手牌、弃牌、魔力
5. 回合制战斗
6. 简单敌人意图
7. 战斗胜利后选一张卡
8. 一个简单地图或连续 3 场战斗

暂时不要优先做：

- 多职业
- 大量卡牌
- 复杂遗物
- 商店
- 事件系统
- 华丽动画
- 完整爬塔流程

## 推荐项目结构

可以把系统拆成：

- `CardData`：卡牌数据，例如费用、名称、描述、效果
- `CardView`：卡牌 UI，负责显示、悬停、拖拽
- `HandView`：手牌区域，负责排列卡牌
- `DeckManager`：牌库、抽牌堆、手牌、弃牌堆、消耗牌堆
- `CombatManager`：战斗流程，回合开始、出牌、敌人行动、胜负判断
- `EffectSystem`：执行卡牌效果，例如伤害、格挡、抽牌
- `EnemyAI`：敌人意图和行动
- `PlayerStats` / `EnemyStats`：血量、格挡、状态
- `RewardManager`：战斗奖励
- `RunManager`：一次爬塔流程，牌组、金币、遗物、地图进度

## UI 节点命名建议

战斗主场景可以类似：

```text
CombatScene
  EnemyArea
  PlayerArea
  HandArea
  EnergyPanel
  EndTurnButton
  DrawPileCounter
  DiscardPileCounter
```

卡牌场景可以类似：

```text
CardView
  CostLabel
  NameLabel
  ArtTexture
  DescriptionLabel
  TypeLabel
```

敌人场景可以类似：

```text
EnemyView
  HealthBar
  BlockLabel
  IntentIcon
  IntentValueLabel
  StatusContainer
```

节点名字尽量稳定，这样后续脚本绑定会更顺。

## UI 交互重点

类《杀戮尖塔》的 UI 成败关键在于玩家是否能一眼看清：

- 我手里有什么牌
- 我现在有多少魔力
- 哪些牌能出
- 敌人下回合要做什么
- 我现在是否安全

优先做这些交互：

- 手牌扇形或横向排列
- 鼠标悬停卡牌放大
- 费用不足时卡牌变灰
- 拖拽卡牌跟随鼠标
- 拖到敌人身上时目标高亮
- 出牌后卡牌飞向目标或进入弃牌堆
- 敌人显示意图图标
- 伤害、格挡、状态数字刷新
- 结束回合按钮状态变化

## 框架调研结论

已在网上查过 Godot 相关卡牌框架。结论是：Godot 生态里没有一个特别成熟、直接等于《杀戮尖塔》的完整框架。更推荐组合使用。

### 首选：Card Framework

链接：https://github.com/chun92/card-framework

用途：

- 做卡牌 UI 和拖拽基础
- 管理卡牌、手牌、牌堆、容器
- 提供卡牌移动动画基础

优点：

- Godot 4.x 插件
- MIT 协议
- Godot Asset Library 上有版本
- 适合接入用户自己设计的 UI

注意：

- 它不是完整的《杀戮尖塔》框架
- 战斗流程、敌人意图、魔力、状态、遗物仍建议自己写

### 架构参考：Deck Builder Tutorial

链接：https://github.com/guladam/deck_builder_tutorial

用途：

- 参考 roguelike deckbuilder 的项目拆分方式
- 学习 `battles`、`characters`、`effects`、`enemies`、`relics`、`statuses` 等目录组织

建议：

- 当作架构参考，不建议完全照搬

### 不建议主用：godot-card-game-framework

链接：https://github.com/db0/godot-card-game-framework

优点：

- 历史较久
- 功能强
- 有卡牌规则、脚本、牌库、Deck Builder 等概念

不建议一开始主用的原因：

- 协议是 AGPL-3.0，闭源商业项目会比较麻烦
- 框架较重，新手容易被框架体系牵着走

## 推荐技术路线

```text
Card Framework
负责：卡牌节点、手牌、拖拽、容器、动画基础

自己实现
负责：战斗流程、魔力、抽牌弃牌、敌人意图、卡牌效果、状态、遗物

参考 deck_builder_tutorial
借鉴：项目结构、Resource 数据、Effect 系统、战斗组织方式
```

## 当前推荐学习路线

```text
1. 看 Godot 关键概念
2. 看节点与场景
3. 跟做第一个 2D 游戏
4. 学一点 GDScript
5. 看 Control / UI 节点
6. 回到卡牌游戏项目
```

对这个项目最重要的 Godot 概念：

- Scene 场景
- Node 节点
- Signal 信号
- Control UI
- GDScript 基础
- Resource 资源数据

暂时可以不用学：

- 3D
- 物理
- 粒子
- 导航
- 多人联机
