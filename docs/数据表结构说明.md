# 魔法少女卡牌游戏数据表结构说明

日期：2026-05-20

本文档记录本项目的策划表设计方式。

表格基础格式规范请查看：`表格规范文档.md`

CardEffect 专门机制请查看：`CardEffect机制文档.md`

项目采用“策划表驱动”的制作思路：

```text
Excel 工作簿：给策划编辑和查看
CSV 表格：给 Godot 读取
Godot 脚本：读取表格并转换为战斗数据
```

## 核心思路

数值、卡牌、敌人、初始牌组等内容尽量不直接写死在脚本里。

脚本负责：

```text
读取表格
校验数据
把表格转换成游戏运行时对象
执行规则
刷新 UI
```

表格负责：

```text
角色基础数值
卡牌基础信息
卡牌效果组合
角色初始拥有卡牌
角色可获得卡池
敌人基础数值
敌人行动
敌人行为逻辑配置
```

## 命名规范

```text
Excel 源表：全英文文件名
CSV 导出表：全英文文件名
表内字段和内容：保持中文，方便策划查看和修改
Godot 代码：只读取 data/tables 下的英文 CSV
```

不要直接手改 `data/tables` 下的 CSV。正常流程是：

```text
修改 design_tables/excel/*.xlsx
运行 导出策划表到CSV.bat
Godot 读取 data/tables/*.csv
```

## 卡牌表

Excel 源表：

```text

```

导出 CSV：

```text
data/tables/Card.csv
```

用途：

记录卡牌的基础信息，不直接展开每个效果的详细执行逻辑。

当前字段：

```text

卡牌名称
费用
卡牌种类

是否消耗

描述
说明
```

说明：

- 每张卡牌至少有 1 个卡牌种类。
- 每张卡牌可以有多个卡牌种类。
- 多个效果用分号连接。

示例：

```text

星光变身
效果列表：
  effect_gain_magic_defense_70
  effect_gain_magic_max_3
  effect_gain_current_magic_3
  effect_enter_transform
```

## 系统配置表

各个系统拥有独立配置表。当前已经建立：

```text
GameConfig：全局配置，例如默认抽牌数、默认手牌上限
ResourceConfig：资源配置，例如生命、魔力、魔力护盾、发情值
DamageTypeConfig：伤害类型配置
StatusConfig：状态配置
FormConfig：形态配置
PileConfig：牌区配置
TurnPhaseConfig：回合阶段配置
TargetTypeConfig：目标类型配置
CardTypeConfig：卡牌种类配置
EnemyIntentConfig：敌人意图配置
```

`Enum.xlsx` 是策划查阅用枚举说明表，不导出为运行时 CSV。

## 当前原则

- Excel 和 CSV 文件名必须使用英文。
- 表格字段先保持中文，方便中文策划语境使用。
- 每条数据必须有稳定 ID。
- 表格可以显示中文名称，但脚本引用尽量使用 ID。
- 多个 ID 用分号连接。
- 复杂逻辑不强行塞进表格，必要时交给脚本。

## 2026-05-24 战斗 Demo 表格调整

最低战斗 demo 采用以下临时稳定结构：

```text
Character：魔法少女配置表
Enemy：怪物配置表
Card：玩家卡牌和怪物行动卡的统一定义表
CardEffect：玩家卡牌和怪物行动卡的统一效果表
StarterDeck：单位初始牌组或怪物行动组
```

`Character` 和 `Enemy` 不合并为新表，但都按战斗单位配置使用，并统一保留以下可选字段：

```text
unit_type
battle_image_path
portrait_path
hit_motion_profile
```

`StarterDeck` 的单位字段已经从早期的 `character_id` 调整为：

```text
unit_id
```

它既可以配置魔法少女初始牌，也可以配置怪物可用行动卡。

怪物行动第一版已经迁移到 `Card` 表：

```text
card_enemy_assault
card_enemy_miasma_shield
card_enemy_hypnosis_ray
```

通过 `owner_type = enemy` 区分这些卡只能由怪物使用。`EnemyAction` 暂时作为旧结构保留，后续确认无依赖后可以删除或转为策划备注表。
