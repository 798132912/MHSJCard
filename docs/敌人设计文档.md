## 敌人设计原则

- 敌人也使用数据驱动结构。
- 敌人的行动可以由敌人卡牌、技能或行为逻辑组合而成。
- 敌人的行为逻辑需要允许手动编写。
- 第一版敌人先支持单敌人战斗，底层预留多敌人扩展。

## 敌人基础字段

一个敌人至少包含：

```text
id
名称
最大生命值
当前生命值
魔力护盾
意图
拥有的敌人卡牌
行为逻辑
标签
```

## 敌人行为逻辑

敌人的行为逻辑用于决定敌人每回合使用哪张敌人卡牌或技能。

第一版支持以下行为逻辑模式：

```text
固定循环
随机选择
条件选择
手动脚本
```

### 固定循环

敌人按照预设顺序循环使用卡牌。

示例：

```text
第 1 回合：袭击
第 2 回合：瘴气护盾
第 3 回合：催眠光线
然后从第 1 回合重新循环
```

### 随机选择

敌人从可用卡牌中随机选择一张。

可以给每张卡牌设置权重。

### 条件选择

敌人根据战斗状态选择行动。

示例：

```text
如果自身魔力护盾 <= 0：
  使用 瘴气护盾
否则如果玩家敏感值 < 30：
  使用 催眠光线
否则：
  使用 袭击
```

### 手动脚本

敌人的行为逻辑可以由用户编写。

实现时，每个敌人可以指定一个行为脚本，脚本接收当前战斗上下文，并返回本回合要使用的敌人卡牌或技能。

建议接口：

```text
输入：
  当前回合数
  敌人当前生命值
  敌人最大生命值
  敌人当前魔力护盾
  玩家生命值
  玩家魔力护盾
  玩家魔力防御
  玩家发情值
  玩家敏感值
  玩家堕落值
  玩家是否处于魔法少女形态
  敌人可用卡牌列表

输出：
  本回合要使用的敌人卡牌 ID
```

这样后续可以让用户直接编写敌人的判断逻辑，而不是只能使用固定模板。

## 敌人意图

敌人行动前需要显示意图。

意图用于告诉玩家敌人下回合大致会做什么。

第一版意图类型：

```text
攻击
防御
施加负面
混合
未知
```

意图显示建议：

```text
袭击：攻击意图，显示伤害值和发情值增加量
瘴气护盾：防御意图，显示获得护盾值
催眠光线：施加负面意图，显示敏感值增加量
```

## 敌人卡牌

敌人卡牌不一定进入玩家牌堆。第一版中，敌人卡牌可以理解为敌人行动技能。

### 袭击

```text
名称：袭击
卡牌种类：敌人行动 / 攻击
目标：玩家
效果：
  - 造成伤害
  - 提升目标发情值
```

具体数值待定。

### 瘴气护盾

```text
名称：瘴气护盾
卡牌种类：敌人行动 / 防御
目标：自身
效果：
  - 获得魔力护盾
```

具体数值待定。

### 催眠光线

```text
名称：催眠光线
卡牌种类：敌人行动 / 负面
目标：玩家
效果：
  - 提升目标敏感值
```

具体数值待定。

## 第一版敌人

### 堕落的学生

```text
名称：堕落的学生
定位：第一版基础敌人
拥有的敌人卡牌：
  - 袭击
  - 瘴气护盾
  - 催眠光线
行为逻辑：可手动编写
```

默认行为逻辑暂定：

```text
如果自身魔力护盾 <= 0：
  使用 瘴气护盾
否则如果玩家敏感值 < 20：
  使用 催眠光线
否则：
  使用 袭击
```

默认数值待定：

```text
最大生命值：待定
袭击伤害：待定
袭击提升发情值：待定
瘴气护盾获得护盾：待定
催眠光线提升敏感值：待定
```

## 待定问题

- 敌人是否拥有魔力防御。
- 敌人是否拥有发情值、敏感值和堕落值。
- 敌人卡牌是否需要和玩家卡牌使用同一套卡牌数据结构。
- 敌人行为脚本用可视化条件配置，还是直接写 GDScript。
- 敌人意图是否完全公开数值，还是只显示大致类型。
