## 敌人设计原则

- 敌人也使用数据驱动结构。
- 敌人的行动可以由敌人卡牌、技能或行为逻辑组合而成。
- 敌人的行为逻辑需要允许手动编写。
- 第一版敌人先支持单敌人战斗，底层预留多敌人扩展。
- 敌人可以围绕某一种或多种魔法少女状态数值设计，例如发情值、敏感值、堕落值、恐惧值、羞耻值、依赖值。
- 敌人的攻击不只造成生命或防御伤害，也可以提高、读取或利用这些状态数值。

## 敌人基础字段

一个敌人至少包含：

```text
id
名称
最大生命值
当前生命值
魔力护盾
意图
拥有的敌人卡牌
行为逻辑
标签
```

## 敌人行为逻辑

敌人的行为逻辑用于决定敌人每回合使用哪张敌人卡牌或技能。

第一版支持以下行为逻辑模式：

```text
固定循环
随机选择
条件选择
手动脚本
```

### 固定循环

敌人按照预设顺序循环使用卡牌。

示例：

```text
第 1 回合：袭击
第 2 回合：瘴气护盾
第 3 回合：催眠光线
然后从第 1 回合重新循环
```

### 随机选择

敌人从可用卡牌中随机选择一张。

可以给每张卡牌设置权重。

### 条件选择

敌人根据战斗状态选择行动。

示例：

```text
如果自身魔力护盾 <= 0：
  使用 瘴气护盾
否则如果玩家恐惧值 < 20：
  使用 压迫凝视
否则如果玩家敏感值 < 30：
  使用 催眠光线
否则：
  使用 袭击
```

### 手动脚本

敌人的行为逻辑可以由用户编写。

实现时，每个敌人可以指定一个行为脚本，脚本接收当前战斗上下文，并返回本回合要使用的敌人卡牌或技能。

敌人表中的 `ai_script_path` 负责指定行为脚本。

敌人的可用行动仍然来自表格配置，例如 `starter_deck_id` 对应的怪物行动牌，或 `action_ids` 兜底列表。行为脚本只负责从这些已配置行动中选择一个行动 ID，不负责声明或生成技能。

也就是说：

```text
Enemy.csv：指定这个敌人使用哪个行为脚本
StarterDeck.csv / action_ids：指定这个敌人有哪些可用行动
敌人行为脚本：根据战斗上下文返回其中一个行动 ID
Card.csv / CardEffect.csv：定义该行动实际造成什么效果
```

建议接口：

```text
输入：
  敌人可用卡牌列表
  当前回合数
  敌人当前生命值
  敌人最大生命值
  敌人当前魔力护盾
  玩家生命值
  玩家魔力护盾
  玩家魔力防御
  玩家发情值
  玩家敏感值
  玩家堕落值
  玩家恐惧值
  玩家羞耻值
  玩家依赖值
  玩家是否处于魔法少女形态

输出：
  本回合要使用的敌人卡牌 ID
```

这样后续可以让用户直接编写敌人的判断逻辑，而不是只能使用固定模板。

## 敌人意图

敌人行动前需要显示意图。

意图用于告诉玩家敌人下回大致会做什么，只展示下一次行动，不展示连续多个回合。

第一版意图类型：

```text
攻击
防御
施加负面
混合
未知
```

意图显示建议：

```text
袭击：攻击意图，显示伤害值和发情值增加量
瘴气护盾：防御意图，显示获得护盾值
催眠光线：施加负面意图，显示敏感值增加量
偷窥：负面/强化意图，显示发情值增加、暴露倾向增加和敌人火力增加
压迫凝视：施加负面意图，显示恐惧值增加量
恐惧撕裂：攻击意图，显示基础伤害和恐惧值带来的追加量
```

如果敌人意图会根据玩家状态数值改变，UI 应该尽量展示最终数值，并在详情中说明来源。

示例：

```text
恐惧撕裂
造成 5 + 2 点伤害
追加来源：恐惧值 24
```

### 偷窥

```text
名称：偷窥
卡牌种类：敌人行动 / 负面
目标：玩家
表现：感觉到奇怪的视线
效果：
  - 敌人获得火力
  - 玩家灵力降低
  - 玩家发情值提高，受暴露倾向影响
```

```text

```

## 第一版敌人

### 堕落的学生

```text
名称：堕落的学生
定位：第一版基础敌人
拥有的敌人卡牌：
  - 袭击
  - 瘴气护盾
  - 偷窥
  - 攻击（弱）
行为逻辑：可手动编写
```

默认行为逻辑暂定：

```text
按表格配置的可用行动顺序循环。
当前顺序：
  1. 袭击
  2. 瘴气护盾
  3. 偷窥
魔力防御耗尽后：
  1. 触发自身携带的隐藏效果：眩晕一回合，并出现选项
  2. 后续循环使用 攻击（弱）
```

当前实现方式：

```text
Enemy.csv 的 hidden_effect_ids 挂载隐藏效果 200010
CardEffect.csv 的 200010 在魔力防御耗尽时触发
效果结果：给自身附加 1 回合眩晕
```

默认数值待定：

```text
最大生命值：20
魔力防御：60
袭击伤害：5
袭击提升发情值：8
瘴气护盾获得护盾：6
偷窥提升发情值：5，受暴露倾向修正
偷窥提升暴露倾向：5
偷窥提供火力：1
偷窥降低玩家灵力：1
攻击（弱）伤害：1
```

## 待定问题

- 敌人是否拥有魔力防御。
- 敌人是否拥有自己的状态数值，还是只有玩家拥有这些状态数值。
- 敌人卡牌是否需要和玩家卡牌使用同一套卡牌数据结构。
- 敌人行为脚本用可视化条件配置，还是直接写 GDScript。
- 敌人意图是否完全公开数值，还是只显示大致类型。
- 第一章实际启用哪些状态数值，避免首章数值过多导致 UI 和教学压力过大。
