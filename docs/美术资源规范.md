# 魔法少女卡牌美术资源规范

日期：2026-05-24

本文档记录第一版战斗 demo 所需美术资源的尺寸、格式、命名和表格配置规范。

当前目标是保证资源能稳定接入 Godot，并适配最低战斗界面。后续如果 UI 原型和动画系统升级，可以在本文档基础上扩展。

## 基础原则

- 资源文件统一放在 `assets/` 目录下。
- 文件名使用英文小写、数字和下划线，不使用中文、空格和特殊符号。
- 图片优先使用 PNG。
- 需要透明背景的角色、卡图、头像使用透明 PNG。
- 原始大图可以另外保存，但接入 Godot 的运行时资源按本文档尺寸导出。
- 战斗图表格字段只填写文件名，例如 `player_star_battle.png`；代码会自动补 `res://assets/characters/`。
- 其他资源路径仍填写 Godot 资源路径，例如 `res://assets/cards/card_star_shot_art.png`。

## 推荐目录

```text
assets/
  characters/
    玩家和怪物战斗图、头像
  cards/
    卡牌插图，由 Card.art_path 动态绑定
  enemy_actions/
    怪物行动图
  ui/
    卡牌底图、按钮、图标、状态图标
  backgrounds/
    战斗背景
```

## 战斗单位资源

战斗单位包含魔法少女和怪物。

### 战斗图

用途：

```text
战斗界面中左右对峙的角色主图
```

推荐规格：

```text
尺寸：768 x 768 px
格式：PNG
背景：透明
安全区域：角色主体尽量控制在 680 x 680 px 内
朝向：玩家默认面向右，怪物默认面向左
```

第一版 demo 会把战斗图显示在约 `280 x 280` 的 UI 区域中，因此 768 图可以向下缩放，后续做更大角色展示也够用。

命名示例：

```text
assets/characters/player_star_battle.png
assets/characters/enemy_corrupted_student_battle.png
```

表格字段：

```text
Character.battle_image_path
Enemy.battle_image_path
```

填写示例：

```text
player_star_battle.png
enemy_corrupted_student_battle.png
```

## 卡牌资源

### 卡牌插图

用途：

```text
玩家卡牌中间的插图区域
通过 Card 表的 art_path 字段动态赋予到 CardView.ArtTexture
```

推荐规格：

```text
尺寸：512 x 384 px
比例：4:3
格式：PNG
背景：不要求透明
目录：assets/cards/
```

安全区域：

```text
主体内容不要贴边，四周至少预留 24 px
重要文字不要画进卡图，文字由 UI 渲染
```

命名示例：

```text
assets/cards/card_star_transform_art.png
assets/cards/card_star_shot_art.png
assets/cards/card_magic_defense_art.png
```

表格字段：

```text
Card.art_path
```

说明：

- 卡牌预制体 `CardView.tscn` 不内置具体卡图。
- 每张卡牌的卡图由 `Card.art_path` 填写 Godot 资源路径。
- 程序运行时读取 `Card.art_path`，并赋值给 `CardView` 中的 `ArtTexture`。
- 如果 `art_path` 为空或资源不存在，程序应隐藏卡图或显示占位，不应崩溃。
- 卡图只负责画面，不包含卡牌名称、费用、类型、效果描述等文字。

### 牌堆卡背

用途：

```text
战斗界面中表示抽牌堆、弃牌堆、消耗区等牌堆。
第一版已接入抽牌堆卡背，用于替代纯文本抽牌堆数量。
```

推荐规格：

```text
运行时尺寸：180 x 260 px
高清源图：360 x 520 px
格式：PNG
背景：透明
```

战斗 UI 显示尺寸：

```text
84 x 122 px
```

命名示例：

```text
assets/ui/card_back_draw_pile.png
assets/ui/card_back_discard_pile.png
assets/ui/card_back_exhaust_pile.png
```

说明：

- 卡背图片不绘制数字、文字或“抽牌堆”等标签。
- 卡背中央需要保留可读区域，方便程序叠加剩余数量。
- 消耗区可以使用漩涡、吞噬、裂隙、黑洞等元素，但仍需保持卡背外轮廓，不要画成普通图标。
- 抽牌堆数量文字由 Godot 的 `DrawPileCountLabel` 渲染。
- 当前抽牌堆显示规则：数量为 0 时隐藏卡背；数量为 1-5 时显示卡背和数字；数量大于 5 时只显示卡背。
- 弃牌堆和消耗区固定显示卡背，不叠加数量数字。
- 风格应与卡牌正面区分，建议使用深色卡背、星光、魔法纹样或魔法阵元素。

### 卡牌类型标签

用途：

```text
卡牌底部的类型标签底板，用于显示攻击、防御、法术、变身、状态等卡牌种类
```

```text

格式：PNG
背景：透明

```

在 `360 x 520 px` 卡牌底图中，类型标签建议放置在底部居中区域，预留文字安全区约 `120 x 24 px`。

命名示例：

```text
assets/ui/card_type_attack.png
assets/ui/card_type_defense.png
assets/ui/card_type_spell.png
assets/ui/card_type_transform.png
assets/ui/card_type_status.png
```

### 能量背景

用途：

```text
卡牌费用、临时能量徽章等圆形或宝石形背景
```

推荐规格：

```text
尺寸：160 x 160 px
格式：PNG
背景：透明
文字：不画进图片，由 Godot 渲染当前能量数值
```

显示时可缩放到约 `96 x 96 px`，导出为 160 尺寸是为了保留发光和外圈细节。

命名示例：

```text
assets/ui/energy_orb_full.png
assets/ui/energy_orb_empty.png
```

说明：

- `energy_orb_full.png` 当前用于卡牌费用徽章。
- 玩家状态区的当前魔力显示使用 `energy_orb_full.png` 圆形图标；`bar_magic_empty.png` 与 `bar_magic_full.png` 用于魔力防御条。
- 图标不要包含数字、斜杠、单位名或“魔力”等文字。
- 中央区域需要低纹理、低高光，避免影响 `0/0`、`3/3`、`10/10` 这类数字可读性。
- 外圈可以使用宝石、魔法阵、星光或能量环表现，但不要把强高光放在数字区域。

### 生命值与魔力防御资源条

用途：

```text
玩家状态区和后续敌人状态区的生命值、魔力防御显示。
资源条由“空条底图”和“满条前景图”两张图片叠加显示。
程序通过裁切满条前景图的可见宽度表现当前数值比例。
```

推荐运行时尺寸：

```text
生命值条：320 x 42 px
魔力防御条：320 x 42 px
```

推荐源图尺寸：

```text
生命值条：640 x 84 px
魔力防御条：640 x 84 px
```

格式：

```text
PNG
透明背景
同一资源条的空条和满条必须完全同尺寸、同画布、同边缘位置
```

Godot 显示规则：

```text
源图 640 x 84 px 会在运行时等比缩放为 320 x 42 px。
不要让资源条按原始图片尺寸直接显示。
当前实现使用 TextureRect 叠加，并通过裁切满条容器宽度表现比例。
```

命名：

```text
assets/ui/bar_health_empty.png
assets/ui/bar_health_full.png
assets/ui/bar_magic_empty.png
assets/ui/bar_magic_full.png
```

说明：

```text
bar_magic_empty.png / bar_magic_full.png 表示魔力防御条，不表示当前魔力。
当前魔力仍使用 energy_orb_full.png 这类圆形能量图标显示。
```

绘制规则：

- `*_empty.png` 表示空资源状态，包含外框、暗底、凹槽或破损纹理。
- `*_full.png` 表示满资源状态，只绘制会被裁切的发光填充层，也可以包含和空条严格对齐的内侧高光。
- 两张图叠加后必须在满值时完全对齐，不允许满条比空条偏移、溢出或尺寸不同。
- 满条前景图会从左到右显示：`当前值 / 最大值 = 可见宽度比例`。
- 满条裁切只改变可见宽度，不改变满条图片本身缩放比例。
- 图片内不要绘制数值、斜杠、单位文字或“HP / 魔力”等标签，数值由 Godot 文本节点渲染。
- 数值文字区域建议位于资源条中央，中央 `160 x 28 px` 范围内避免复杂纹理和强高光。
- 资源条四周至少预留 `4 px` 透明安全边，避免缩放和裁切时边缘被吃掉。

生命值条风格建议：

```text
空条：深红、暗紫或低饱和暗底
满条：红色、玫红或暖金高光
主题：生命、心跳、魔法纹路、宝石裂纹
```

魔力防御条风格建议：

```text
空条：深蓝、靛紫或暗色魔法槽
满条：蓝色、青色、紫色或星光渐亮
主题：魔力屏障、防御结界、星光护甲、魔法阵
```

显示规则：

- 生命值条始终显示，只要角色存在。
- 魔力防御条只有 `魔力防御 > 0` 时显示。
- 当魔力防御为 `0` 时，魔力防御空条、满条和数值全部隐藏。
- 当前魔力使用圆形能量图标显示；即使魔力上限为 `0`，也显示当前魔力圆形图标和数值，例如 `0/0`。

## 战斗背景

用途：

```text
战斗界面背景
通过 Level 表的 background_path 字段动态赋予到 CombatScene.BackgroundTexture
```

推荐规格：

```text
尺寸：1920 x 1080 px
格式：PNG 优先；体积过大时可用高质量 JPG
色彩：sRGB
背景：不透明
目录：assets/backgrounds/
```

说明：

- 背景只画场景本身，不画 UI、卡牌、按钮、血条或文字。
- 整体亮度建议偏暗，避免影响卡牌、血条和文字可读性。
- 顶部 `0-100 px` 预留 HUD 区，不放重要人脸、文字或强高光。
- 底部 `650-1080 px` 预留手牌区，降低细节和对比度。
- 左侧玩家区域和右侧敌人区域避免放过于抢眼的主体，防止和角色立绘冲突。
- 中央和敌人背后可以放视觉焦点，例如法阵、月亮、异界裂缝或远景光源。
- 第一版可以先提供一张整图背景；程序默认按屏幕铺满并居中裁切。

命名示例：

```text
assets/backgrounds/bg_battle_classroom_corrupted.png
assets/backgrounds/bg_battle_dark_city.png
assets/backgrounds/bg_battle_moon_ruins.png
assets/backgrounds/bg_demo_trial.png
```

表格字段：

```text
Level.background_path
```

可选分层版本：

```text
assets/backgrounds/bg_battle_dark_city_back.png
assets/backgrounds/bg_battle_dark_city_mid.png
assets/backgrounds/bg_battle_dark_city_front.png
assets/backgrounds/bg_battle_dark_city_fx.png
```

分层说明：

```text
back：远景，不透明，1920 x 1080
mid：中景，透明 PNG，1920 x 1080
front：前景遮挡，透明 PNG，1920 x 1080
fx：静态光效，透明 PNG，1920 x 1080
```

## Godot 导入建议

像素风资源：

```text
Filter：Nearest
Mipmaps：关闭
```

```text

Mipmaps：按需要开启
```

透明 PNG：

```text
Alpha：保留透明
```

UI 图标：

```text
尽量导出为 128 x 128，再由 UI 缩放到实际显示尺寸
```

## 表格接入建议

当前已经有：

```text
Character.battle_image_path
Character.portrait_path
Enemy.battle_image_path
Enemy.portrait_path
```

当前 `Card` 表已有：

```text
art_path

```

第一版含义：

```text
art_path：卡牌或怪物行动插图
frame_path：卡牌底图，不填则使用默认底图
```

## 程序占位规则

当资源路径为空或文件不存在时：

```text
战斗单位显示默认色块
卡牌显示文字按钮
敌人意图显示行动名称
```

这样可以保证策划表和战斗逻辑先跑通，美术资源后续逐步替换。
